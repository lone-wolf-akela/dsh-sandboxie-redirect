# dsh-sandboxie-redirect

给 DSH 增加第四种权限预设 **「写时复制」**：工作区内的写入照常落到真实磁盘；工作区外的写入、修改、删除不会失败，而是落入该工作区专属的 Sandboxie 沙盒副本，真实磁盘不会被写入。三个原有预设（只读 / 仅工作区 / 完全权限）行为不变。

## 简介

- 以权限预设接入，不改动 DSH 应用本体。
- 依赖 Sandboxie-Plus；副本可查看、可恢复、可丢弃。
- 用途是防止误写、提供可撤销性、保持系统目录不被写入；不用于防御恶意程序（Sandboxie 不提供该保证）。

## 术语

| 词 | 含义 |
|---|---|
| 真实磁盘 | 系统里实际存放文件的地方（例如 `C:\Users\…`）。 |
| 沙盒 | Sandboxie 创建的隔离环境；本插件为每个工作区创建一个专属沙盒。 |
| 副本 | 沙盒对"工作区外文件改动"的私有存储（位于 `C:\Sandbox\…`），与真实文件分开。 |
| 沙盒内 / 沙盒外 | 写时复制模式下，shell 命令运行在沙盒内；DSH 应用本体和它的文件工具（读/写/编辑文件）运行在沙盒外。 |
| 合并视图 | 在沙盒内读取文件时，沙盒会把副本内容叠加到真实文件上呈现给命令。 |
| SandMan | Sandboxie-Plus 自带的图形管理界面，可查看、恢复、删除沙盒。 |

## 安装

**前置条件**：先安装 [Sandboxie-Plus](https://sandboxie-plus.com/)（可从其官网下载，或从其 [GitHub 仓库](https://github.com/sandboxie-plus/Sandboxie) 获取安装包）。本插件的所有沙盒都由 Sandboxie 创建和管理。

安装步骤：

1. 将插件放到 `C:\Users\<你>\.dsh\plugins\dsh-sandboxie-redirect\`。
2. 编辑 profile 的补丁文件 `C:\Users\<你>\.dsh\profiles\desktop\cordis.patch.yml`，加入本插件。完整模板见仓库根目录 `cordis.patch.yml.new`，把其中的插件路径改成你的实际路径。核心是三点：
   - 用插件替换 shell 沙箱 provider（禁用原 `sandbox` 行，新增一行 provider）；
   - 给权限预设增加 `copy-on-write` 一项；
   - 模型说明、标题栏沙箱名称、`sandbox_clear` 工具由 provider 自动挂载，无需单独添加。
3. 重启 DSH 客户端。
4. 在权限下拉中选择 **写时复制** 即生效。

更新插件文件时使用 `tools/install.mjs`，并且**必须在沙盒外执行**（即 DSH 会话处于非写时复制模式，或在普通终端里运行）：写时复制模式下沙盒内的写入会被重定向、落不到真实磁盘，脚本会检测到并拒绝，避免"报成功但没生效"。

```powershell
$node = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
& $node .\tools\install.mjs
```

## 功能

### 写时复制预设

选中后，shell 命令在沙盒内运行：

| 位置 | 行为 |
|---|---|
| 工作区内的写入、修改、删除 | 直接作用于真实磁盘 |
| 工作区外的写入、修改 | 命令报成功，但改动只发生在该工作区的沙盒副本中，真实磁盘不受影响 |
| 工作区外的删除 | 真实文件保留，副本中只记录删除标记 |

DSH 的文件工具（读/写/编辑文件）在沙盒外运行，仍按「仅工作区」判定：工作区内可写，工作区外拒绝。因此：想读"沙盒视角"的文件，用 shell 命令读（见下文"读侧分歧"）。

该预设下，会话的策略文本会追加一段说明，告知模型本模式的行为与注意事项。

### 标题栏的沙箱名称

写时复制模式下，标题栏会显示当前沙盒名称（如 `dsh_able_willow`，悬停可见副本根路径）。它只在两个条件同时满足时出现：该会话的预设是写时复制，且该工作区确已创建沙盒。因此第一次命令后才出现，切换预设或清理沙盒后消失。

### 权限下拉图标

「写时复制」预设在下拉与底部按钮中带有图标（复制双矩形），随主题配色。

### sandbox_clear 工具

会话内可用 `sandbox_clear` 工具查看或清除本工作区的沙盒副本：`mode: "inspect"` 仅查看（文件数、占用），`mode: "clear"` 删除副本与配置。任何权限模式下都可用，且只能操作本工作区的沙盒。

## 用户注意事项

- **读侧分歧（重要）**：同一个路径，不同工具看到的内容可能不同。
  - shell 命令运行在沙盒内，读到的可能是合并视图：如果之前有命令在工作区外写过该文件，命令看到的是沙盒副本里的版本。
  - DSH 的文件工具运行在沙盒外，读到的一直是真实磁盘上的版本。
  - 因此，验证"命令在工作区外写了什么"，用 shell 命令读；验证"真实磁盘有没有被改动"，用 DSH 的文件工具（或资源管理器）读。
- **副本位置**：普通路径在 `<沙盒根>\drive\<盘符>\<路径>`；用户目录下的路径在 `<沙盒根>\user\current\<相对路径>`。沙盒根为 `C:\Sandbox\<用户>\<沙盒名>\`。
- **磁盘占用**：副本不自动回收，会持续累积。
- **`C:\Windows\Temp`**：修改其中已存在的文件可能被拒（Sandboxie 原生行为，非本插件所致）；新建与删除不受影响。
- **并发**：同一工作区的并发命令共用一个沙盒，互相可见。
- **升权**：写时复制下，若某命令需要更大权限而发起升权，该次调用会整体在沙盒外运行，不受沙盒限制；下一条命令回到沙盒。
- **写回**：副本改动默认不回灌真实磁盘。需要恢复时，在 SandMan 中查看并恢复相应文件；本插件的清理工具只做删除，不做写回。

## 手动管理沙盒

```powershell
node bin\dsh-sbie-run.mjs --manage list                    # 列出受管沙盒
node bin\dsh-sbie-run.mjs --manage clean "<工作区>"         # 清理某工作区的沙盒
node bin\dsh-sbie-run.mjs --manage delete-box <沙盒名>      # 删除指定沙盒
```

`--manage` 必须在沙盒外运行（普通终端，或 danger-full-access 会话）：沙盒内进程看不到沙盒列表。

也可以通过 sandboxie plus 自带的 GUI 界面管理对应的沙盒。
